Bootstrapping: Kite compiled by Kite

kite
stage0  archive/rust-stage0   Rust seed compiler (kept forever)
stage1  compiler/             the compiler written in Kite, built BY stage0
stage2  stage2/               stage1 compiling itself — must give the same LLVM IR as stage1
kite
./build.sh          # stage0 → stage1 (→ stage2 when the port is complete)
./build.sh test     # + differential tests Kite vs Rust
./build.sh status   # which phases are ported

Progress

phase status
lexer, parser, diagnostics ✅ identical to Rust on every sample (tokens, AST, spans)
desugar (classes, match, data enums, defaults, named args, *args, unpacking) ✅ identical to Rust on every sample, errors included
prelude injection (core.ki, StrMap_<T> instances) ✅ kitec inject FILE identical to Rust on every sample
prelude injection next
sema, IR, codegen, driver todo (target: 0.4.0)

When stage1 = stage2, compiler/BOOTSTRAPPED is written and scripts/package-release.sh --compiler auto starts shipping kitec instead of the Rust binary.

How a port is verified

Each phase is compared with the Rust one on all .ki files of the repository through canonical dumps (scripts/difftest.sh). kitec tokens FILE, kitec ast FILE, kitec desugar FILE, kitec inject FILE, kitec --capabilities expose them.

Status: complete (0.4.0)

Every phase is ported and ./build.sh proves the fixed point: stage1 (kitec built by the Rust seed) compiles compiler/ into stage2, stage2 compiles it into stage3, and the LLVM IR of the three is identical (stage1 is compared with its string constants sorted, since Rust emits them in HashMap order). compiler/BOOTSTRAPPED records the date. The shipped kite is compiler/target/kite (= stage2); it only needs libc and clang. Dev commands for each phase remain: kitec tokens|ast|desugar|inject|sema|ir|ll FILE.

Pitfalls found on the way (see also the notes in desugar.ki): arena reallocation while a pointer into it is held (loops over ast.nodes[i].kids, assignments whose right side creates nodes) and quadratic string building (use lists + join).

0.4.2: the compiler imports pieces

The compiler's sources now use the default pieces (use std.path, ...). Stage 1 is still built by the Rust seed, which was taught to resolve use std.<piece> from the registry (archive/rust-stage0/src/resolve.rs); stages 2 and 3 use the Kite resolver. Keep the pieces the compiler imports compatible with the seed: no piece.function() calls, no \x/\e/\r/\0 string escapes (the seed's lexer reads them as plain letters; use chr_byte(n)).
